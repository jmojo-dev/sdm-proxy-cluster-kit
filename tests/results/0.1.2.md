# Verification of kit 0.1.2

These results cover the local build whose bootstrap SHA-256 is `011cd8cfad481458dbc92cd4333019d41d22ec892c40cdb03b37fde5e4b24329`. The standalone kit SHA-256 is `dcf2ba1d1076649f803b8973e40f1a0097531a01282d22466dcf0b3c1a9bf924`.

## Live PostgreSQL connection, November 24, 2026

A signed-in StrongDM desktop client connected through a single worker installed by the bootstrap on a fresh Ubuntu 24.04.5 LTS ARM64 QEMU guest in OrbStack. PostgreSQL 17.10 ran in a separate container with no published database port.

| Check | Observed result |
| --- | --- |
| Fresh installation | The kit verified the vendor archive for worker 56.26.0. The worker updated itself to 56.33.0 on startup. The kit waited for readiness from the new process and exited successfully. |
| SQL access | Using only the local StrongDM listener and no database password, `psql` retrieved a random value seeded independently in the database. PostgreSQL reported the expected read-only role and the worker's bridge address as the connection source. |
| Worker outage and recovery | Stopping the worker made the query fail while PostgreSQL continued accepting connections. Starting the same worker restored access and returned the original value. |
| Repeat installation | An open SQL session retrieved the value before and after the installer ran again. Both the PostgreSQL backend PID and the systemd worker invocation stayed the same. |
| Diagnostics | Check mode returned 25 successful checks, two warnings and zero failures. The warnings flagged the restart and recent error entries during the vendor's startup update. |

After cleanup, the signed-in account had zero matching resource entitlements. The test cluster, authentication key, database resource, containers, volume and network were removed.

## EC2 verification, November 23, 2026

Amazon Linux 2023 on x86-64 and Ubuntu 24.04.5 LTS on ARM64 booted their native AMIs and verified all three artifact checksums. On both hosts, the vendor CLI sealed test credentials, preserved them on reuse, rotated them on request and read the sealed names after reboot. Lifecycle tests used a fixture worker to exercise interrupted provisioning, readiness and rollback. Debug cleanup passed on both distributions after correcting a test assertion for Ubuntu's fallback log directory.

Public release download and attestation verification, live Delinea authentication, and multi-worker failover were outside these runs.
